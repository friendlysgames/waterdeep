## Key Decisions

### GitHub Pages over embedded Artifact
**Decision:** Deploy as a GitHub Pages site built from the repo's markdown files rather than a manually-rebuilt Claude Artifact.
**Reasoning:** CI rebuilds automatically on content pushes; the DM doesn't need to invoke a skill or wait for a session to update the compendium.

### Build script on master, feature branch for viewer edits
**Decision:** All commits that must reach GitHub Pages go to master via `mcp__github__push_files` (the only way to write to a branch-protected master). Local viewer template edits are committed to `claude/artifact-github-pages-0gn1s7` and then pushed to master via MCP.
**Reasoning:** Branch protection on master blocks `git push origin master` with 403. The MCP tool bypasses this. Both the feature branch and master must stay in sync for the stop-hook to pass.

### Split-pane architecture
**Decision:** `body.split-view` CSS class toggles a secondary reading pane. Each pane (`#pane-primary`, `#pane-secondary`) is independently scrollable with its own breadcrumb header and article element (`.page-content` class, not ID). Active pane tracked via `activePaneId`. The toolbar breadcrumb syncs to whichever pane is active. A ⧉ button appears on page list items on hover and opens that page in the secondary pane. The split toggle and ⧉ button are hidden on mobile (≤768px).
**Reasoning:** User asked to open two journal pages simultaneously — e.g., a quest event and the location it references.
> "We now need a way to open two journal pages at once, so one may read both a quest and the location it relates to." — User, this session

### GM Mode removed
**Decision:** Removed the GM Mode checkbox from the toolbar entirely.
> "You can remove the GM Mode checkmark, I'm the only one that's gonna use it" — User, this session

### Journal sidebar button moved right
**Decision:** The journal sidebar toggle (☰) is now the rightmost toolbar button.
> "move the journals sidebar (not the pages sidebar) button to the right" — User, this session

## Rules and Instructions

All prior standing rules still apply. New rules from this session:

- **Master writes via MCP only:** `git push origin master` is blocked by branch protection (403). All commits destined for master must go through `mcp__github__push_files`. This applies to the viewer template, build script, workflow, and docs output.
- **Stop hook requires feature branch push:** The stop hook (`~/.claude/stop-hook-git-check.sh`) checks for unpushed local commits. After committing to `claude/artifact-github-pages-0gn1s7`, always run `git push -u origin claude/artifact-github-pages-0gn1s7` before ending the turn.
- **`docs/index.html` is a build artifact:** Never edit it by hand. Regenerate with `python3 scripts/build-viewer.py` or let CI do it on the next master push.
- **Viewer template is the single source of truth:** All UI changes go to `.claude/skills/update-campaign-viewer/references/viewer-template.html`. CI reads it from master at build time — template changes on the feature branch only affect the live site after being pushed to master via MCP.

## Problems Solved

- **CI reading stale template:** The workflow reads the template from master at build time, so feature-branch edits don't reach the live site until pushed to master. Fix: always push template changes to master via `mcp__github__push_files` after committing to the feature branch.
- **Stop hook blocking turn end:** Local commits on the feature branch weren't pushed to remote. Fix: `git push -u origin claude/artifact-github-pages-0gn1s7` after each turn with local commits.
- **`#page-content` ID → `.page-content` class:** The split-pane needs two article elements with identical styling. Changed all CSS selectors from `#page-content` (ID) to `.page-content` (class) via `replace_all` so both panes share the same typography and spacing.
